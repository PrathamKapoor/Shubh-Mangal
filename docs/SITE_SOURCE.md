# Source bundle seed prerequisite

The `seed(db, { source })` programmatic interface accepts a validated source bundle containing a repository-relative layout JSON path, a site name, explicit asset references, source provenance, and demo amenity titles. The default remains the Shubh Mangal source. Layout metadata must satisfy `projectionFromLayout`; layout plot IDs must be distinct and the plan view box finite and positive. Seeding records the selected source path and rejects a database already containing a different source bundle. Use an isolated database for an alternate fixture. Older records without this marker are treated as legacy Shubh Mangal records. `SITE_SOURCE_CONFIG` selects a bundle for database commands; normal server startup explicitly refuses alternate bundles until the browser and assets are site-configurable. Startup checks legacy source identity without requiring the current layout file to match an old legacy hash.

`tests/fixtures/second-site/` is synthetic and uses UTM 32N. Run `node --test tests/site-source.test.mjs` to verify seeding and the mixed-source guard. This is a seed-path test, not a second-site deployment: the normal server, browser, import validation, download preparation, branding, and several asset and amenity references still use Shubh Mangal defaults. The asset references in this bundle are not yet wired into the app. A source bundle must not be treated as making a different development ready for production.
