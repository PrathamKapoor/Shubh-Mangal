# Optional Google basemap

**My location** makes one browser request after permission. It shows a centre indicator and reported accuracy circle in metres; off-site fixes remain valid. **Clear location** removes it. There is no follow mode or background watch. Hidden pages cancel pending callbacks and clear the point. A fix expires after 60 seconds (up to 5 seconds future clock allowance); reported accuracy over 100 m displays a low-accuracy warning, not an engineering/survey tolerance. No parcel-level presence is inferred. Secure context/HTTPS is required (localhost is a browser development exception).

Open `/explore` → **Google Maps**. The local Plan, Illustrated, 3D and Original views remain available. Select a plot from the common list or a visible geographic boundary; selection, filters, compare and URL history continue to use the existing record. **Show entire site** is separate from visitor location. Roadmap/Hybrid use Google's own basemap and attribution. Field alignment is unverified.

Default: disabled, no Google script request. Set `VITE_GOOGLE_MAPS_ENABLED=true` and `VITE_GOOGLE_MAPS_KEY=` to an operator-owned, browser-visible restricted Maps JavaScript API key, then rebuild. Set `GOOGLE_MAPS_ENABLED=true` on the production Express process to enable its provider CSP. A map ID is not required for the native Map/Data integration. Server-only credentials must never use VITE_ prefixes.

Enable Maps JavaScript API and billing in the operator's Google Cloud project. Restrict the key to this API and the exact local/staging/production website referrers, using separate keys where appropriate. Set quotas, budget alerts and billing monitoring with the operator. Do not paste a key into code, test fixtures or issue reports. Current references: [key configuration](https://developers.google.com/maps/documentation/javascript/get-api-key), [billing](https://developers.google.com/maps/documentation/javascript/usage-and-billing).

Implementation uses native official [async script loading](https://developers.google.com/maps/documentation/javascript/load-maps-js-api), `google.maps.Map`, `Data.addGeoJson`, Data style/click listeners and native fitBounds/map types. A small native adapter fits the existing React state without an additional wrapper dependency; vis.gl is an alternative if future overlay lifecycle complexity warrants it. Provider code loads only on opening this view. No iframe, scraped tiles or images substitute for the API. Source originals/3D are not requested to initialize Google view, although the existing explorer still loads its source layout JSON.

Published features arrive with project and inventory data through `/api/public/snapshot` and match inventory by UUID, geometry ID and version. Duplicates/mismatches are suppressed. Failed snapshot refreshes mark data stale and hide reviewed overlays until revalidation. Local/offline source shapes are a separately labelled provisional layer, never approved identities. Reviewed roads/site/amenities are not fabricated from the decorative plan. See [API contract](API.md).

Production Express adds per-response script nonces and strict-dynamic only when enabled, and allows required Google image/connect/font/frame/worker sources following [Google CSP guidance](https://developers.google.com/maps/documentation/javascript/content-security-policy), consulted 2026-11-15. Google currently documents unsafe-eval for this client; it is enabled only under the provider switch. Existing inline style policy is retained for React/native map styles. The no-provider script policy stays self-only. Keep reverse proxy protections; do not add a conflicting second CSP. `deploy/nginx.conf` forwards application headers. Verify actual HTTPS responses and provider requests in staging; a local header test is not live CSP acceptance.

Opening this view contacts Google and is subject to its mapping/privacy terms; provider request context and the browsed map viewport are separate from application lead data. Browser location is an intentional separate action. The application does not persist that location or attach it to enquiries, URLs or analytics. Read the current privacy page and Google terms before enabling. Never trace/export Google imagery as a new overlay dataset.

Missing/disabled key gives a Plan fallback. Network/script timeout offers retry; authorization/billing/referrer rejection explains reconfiguration and reload. Quota/provider errors may require checking the Google Cloud console. No error counts as a successful live map. Roll back by rebuilding with `VITE_GOOGLE_MAPS_ENABLED=false` and restarting Express with `GOOGLE_MAPS_ENABLED=false`; the rest of explorer remains runnable.

Checks: Node tests exercise the loader, matching, duplicates, cleanup, failures and headers; Playwright uses a controlled provider network adapter. Live acceptance still requires an authorized staging origin/key, actual Google imagery at this site under production CSP, HTTPS device geolocation, billing/quota checks and reviewed field access coordinates. Android Chrome/iPhone Safari hardware and physical route testing remain pending.
