The supplied PNGs are RGBA: temple is 1312×1199, the other four are 1536×1024. All have transparent outer pixels; fountain, garden, clubhouse and gate also contain broad translucent glows/shadows. An attempted image-generation cleanup did not reliably remove those glows while preserving the original concepts, so those generated variants were discarded. The map and cards use the supplied artwork, resized proportionally to at most 640 px and encoded as WebP at quality 0.9 by `scripts/optimize_concepts.mjs`; alpha is preserved. Individual outputs are 59,992–114,298 bytes, 394,010 bytes combined versus 11,273,017 bytes for the original five. The map uses aspect-preserving SVG viewports to trim near-transparent margins, then clips artwork to the indicated source areas. A narrow clip-only bridge joins near-matching shared temple/garden edges; original polygon paths are unchanged. Illustrated grass and paths do not represent a verified site design. The script refuses to overwrite an existing derivative. If a WebP cannot load, the original PNG is used; if that also fails, a simple marker and a clear card message remain.

The newer top-down images have transparent outer areas and baked-in illustrative landscaping/shadows. Their aspect-preserving viewports and per-area clips are presentation only. The five WebP concept copies total about 708 KB; textures add about 178 KB and load only in Colony view. `scripts/optimize_map_assets.mjs` creates maximum-768px concept and maximum-512px texture copies at quality 0.86, refuses to overwrite existing derivatives, and leaves all originals untouched. The supplied road's white lane markings are outside the SVG crop; the image is not used as a whole roadway. If a texture fails to load, the underlying plain status and road fills remain usable.

The pool and outdoor-gym attachments have transparent surroundings; the combined concept has an opaque white background and is reference-only. For the map copies, the alpha bounding box at threshold 32 was used only to trim near-transparent padding, then each image was proportionally reduced to a maximum of 768 pixels using Lanczos and saved as WebP at quality 88. Pool crop: `(54,102)–(1477,862)`, output 768×410, 113,752 bytes. Gym crop: `(50,68)–(1515,920)`, output 768×447, 126,994 bytes. No source image was overwritten. The map has a native SVG fallback if a concept image fails.

The clubhouse and gate derivatives were created with the built-in image editing service. For the clubhouse the instruction was to remove the pool and replace it with matching lawn while preserving the building, landscape, proportions and transparent exterior; for the gate it was to remove the entire baked-in roadway and keep the pillars, beam and compact planting against transparency. Both were inspected before use. Image generation can alter visual details and neither result is evidence of the real site. The owner must approve the concepts and their publication rights.

The source polygons and a road/plot exclusion mask fill the amenity grounds. Paths and small planting details are illustrative SVG elements; foliage detail samples the supplied corner concept. These do not represent a verified landscaping design. The lower-left gate, illustrative perimeter opening and short road continuation beyond the source drawing are presentation choices pending owner confirmation, not proof of a constructed gate, wall or external road. An owner-reviewed visual placement may be saved independently of plot measurements and published only after review; original plot paths and the original plan remain available.

No actual photographs, measured interactive 3D models, panorama or drone footage were supplied. The PNG renderings are 2D overlays. The schematic 3D view uses Three.js and React Three Fiber; an optional Google basemap is disabled by default. The SVG renderer does not require WebGL. If real models or imagery are supplied later, check their licence, attribution, geographic accuracy, size and device fallback before use; label concepts and proposed facilities honestly. Binary model uploads are not enabled.

The local 2D renderer uses browser-native SVG; the optional schematic 3D and Google basemap have separate dependencies and provider terms. `proj4` is used by shared projection code. Review the lockfile and individual dependency licences and notices for a formal distribution audit. Supplied asset publication rights are still an owner decision.

Image uploads are limited to 2 MiB raster images, checked for a matching format signature, saved outside the release tree under `MEDIA_DIRECTORY`, and served through an API only when approved published content references them. Owners should remove sensitive EXIF metadata before upload and verify consent for people/property shown. Back up the media directory along with the database; it is not included in a PostgreSQL dump. Removing a content reference withdraws public access but does not automatically delete the private staged file or its audit record.
